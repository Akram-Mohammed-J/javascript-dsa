Sliding Window — Visual Guide

The three sliding window patterns, shown as real diagrams — not ASCII art.

The one rule that never changes: right moves forward every iteration, no exceptions. left only moves forward inside a shrink step — when and why it moves is the only thing that differs between problems.

1The Core Picture

Every sliding window problem maintains a contiguous range inside an array, marked by two pointers.

The window is everything between left and right, inclusive on both ends.

2Flavor 1 — Fixed-Size Window

Use when: the problem gives an exact window size k upfront — sum of every k consecutive elements, average of k days, and so on. 

function fixedWindow(arr, k) {
    let windowValue = 0;
    let best = -Infinity;

    for (let right = 0; right < arr.length; right++) {
        windowValue += arr[right];              // grow

        if (right >= k - 1) {
            best = Math.max(best, windowValue);   // record
            windowValue -= arr[right - k + 1];     // shrink automatically
        }
    }
    return best;
}
just added (grow) just removed (shrink) current window
arr = [2, 1, 5, 1, 3, 2], k = 3 — the window slides by exactly one position each step, best sum found is 9.
Core thing to remember: left never gets its own variable — it's always right - k + 1, computed directly. Shrinking is automatic, not a decision.

3Flavor 2 — Longest Valid Window (Shrink Only When Broken)

Use when: finding the longest substring/subarray satisfying a property — e.g. "longest substring without repeating characters." 

for (let right = 0; right < s.length; right++) {
    include(s[right]);                  // grow — always happens

    while (isInvalid()) {               // shrink only if broken
        exclude(s[left]);
        left++;
    }

    best = Math.max(best, right - left + 1);   // record AFTER fixing
}
window is valid window is invalid (duplicate found) character being dropped by left
s = "abcabcbb" — longest run without repeats is 3 ("abc").
Core thing to remember: the while-loop runs while invalid. The moment it's fixed, stop shrinking and record. You always record after the window is guaranteed valid.

4Flavor 3 — Shortest Valid Window (Shrink While Still Valid)

Use when: finding the shortest window satisfying a property — e.g. "minimum window substring" or "smallest subarray with sum ≥ target." 

for (let right = 0; right < nums.length; right++) {
    include(nums[right]);                // grow — always happens

    while (isValid()) {                  // shrink WHILE valid
        best = Math.min(best, right - left + 1);   // record BEFORE shrinking further
        exclude(nums[left]);
        left++;
    }
}
window is valid (target met) window is not valid yet being squeezed out while still valid
nums = [2, 3, 1, 2, 4, 3], target sum ≥ 7 — shortest valid window found is length 2 ([4, 3]).
Core thing to remember: this while-loop condition is the opposite of Flavor 2 — loop while valid, not while broken. Record inside the loop, every single step, because each shrink (while still valid) is a new, smaller candidate.

7Why the Nested Loop Isn't O(n²)

left never resets backward — across the entire run of the algorithm, it moves forward at most n times total, not per outer iteration. So even though the loop looks nested, the total combined work is bounded by n + n = O(n). This is called amortized analysis.

The one-paragraph summary: Sliding window maintains a contiguous range with two pointers, where right always advances and left advances only during a shrink step. A fixed-size window shrinks automatically and unconditionally. A longest-valid-window search shrinks only when the window breaks a rule, recording right after fixing it. A shortest-valid-window search shrinks for as long as the window stays valid, recording a new candidate at every single step of that shrink. All three run in O(n) because left can move forward at most n times, no matter how the loops are nested.
